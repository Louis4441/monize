# v1.17.0

The **calendar and rules** release.

The Transactions and Investments pages can now be read as a **month calendar**, with daily balances and notes you can pin to a day or a span of days. **Transaction rules** fill in the category, payee, description and tags for you as transactions arrive. The register **sorts by any column**, the dashboard widgets gained the options people asked for, and investment charts and figures were checked end to end so the numbers agree with each other.

Operators should read [For operators](#for-operators): Monize can now run as more than one backend replica, and automatic backups can be copied off the machine.

## Calendar view

- **A Table / Calendar switch** on the Transactions and Investments pages. The table stays the default.
- Each day shows its transactions, and optionally the day's **balance** (projected days are marked as such) or its **daily change**.
- **Day notes** in sticky-note yellow, on one day or stretched across several.
- Click the month heading to **jump to any month** by typing it (`Mar 1998`, `2026-03`), or swipe left and right on a phone.

## Transaction rules

**Tools -> Rules** lets you write WHEN / IF / THEN rules: when a transaction is created or imported, if it matches your conditions (payee, amount, account, day of month, tags and more), set its category, payee or description, add or remove tags, or send it to the **AI review queue**. A rule never changes an amount or moves money. You can preview a rule, run it over existing transactions, and undo the run. The AI assistant can create and manage rules for you.

A short **guided tour** of rules, from the Tools menu through the editor, the Test panel and the AI review inbox, is offered from the What's New digest.

## Transactions

- **Sort the register by any column** -- date, account, payee, category, description, ref #, amount or status. The running balance stays correct in both date directions and is hidden under any other sort, where it would be meaningless. On a phone, sorting is a row of chips.
- A long payee name no longer pushes Amount and Balance off the screen: it wraps at Normal density and is shortened with "..." at Compact and Dense.
- The reference number is no longer repeated under the payee.
- Posting a scheduled buy or sell: changing the quantity keeps the total and recalculates the price, and changing the price keeps the quantity.
- CSV imports read European decimal commas correctly (`18,36` is 18.36, not 1836).

## Dashboard

- Every widget title links to its full report.
- New timeframes: month-to-date on the spending and income widgets, year-to-date on Monthly Spending Trend, and 1W / MTD / YTD with the change in money and percent on Portfolio Value.
- **Top Movers** ranks by amount or percent, and only compares moves from the same trading day.
- **Expenses by Category** now agrees with the Spending by Category report, can roll up to top-level categories, and "Other" opens to show what it contains.
- **Upcoming Bills** shows everything upcoming, as a list or a small calendar.
- Asset class view on Security Type Allocation, and many more exchanges recognised by Geographic Allocation.

## Investments

- **Portfolio Performance** sits beside the value chart and gains 2Y, 5Y, 10Y and All Time, shown only when your history goes back that far.
- **Portfolio Value over Time** gains a custom date range. YTD now starts from last year's closing value.
- The charts' starting point, their "since the close of" caption and the Value Change figure now all describe the same day, and short-range charts value each day at the holdings you actually had that day.
- A broad correctness pass on investment reporting: holdings, cost basis, sold-out positions, historical exchange rates, and missing prices shown as missing rather than zero.
- **New price sources: London Stock Exchange and Deutsche Börse (Frankfurt).**
- The GEM strategy report says which security's price history is too short, and a new button fetches another year of it.
- The daily portfolio movement alert keeps working when you hold a security whose price you enter by hand.

## Reports

- **Break down by tag key** in Income vs Expenses and Cash Flow. Transfers you tag (for example, money drawn from a retirement account to live on) appear as their own figure, never counted as income or expenses.
- Monthly Comparison measures account performance as a return, and its breakdown takes less room on a phone.

## Currencies

- The **Currency Rate History** dialog lists the stored rates, and a **Fill gaps** button fetches any missing dates, not just older ones.
- A Microsoft Money import can no longer overwrite the shared market exchange rates everyone else uses.

## Security and sign-in

- Fixes from an OWASP security review, mostly around what a delegate can see and change.
- Two-factor authentication shows the same state in Settings that sign-in enforces, and an account stuck half-disabled can be repaired.
- A weak `JWT_SECRET` raises an admin alert and banner.

## Everyday fixes

- Help icons open on phones and tablets; they were hidden there before.
- The Tools menu is reordered: Payees, Categories, Securities, Currencies, Institutions, Tags, Rules, Import Transactions.
- Dashboard cards grow with their content on iPad.
- The portfolio summary no longer causes periodic CPU spikes.
- Demo payees have contact details and logos.
- Remaining untranslated English strings were translated.

## For operators

- **Multiple backend replicas.** `CLUSTER_MODE=multi` runs several backend replicas using PostgreSQL alone, with no Redis. Scheduled bills, emails and alerts are sent once, not once per replica. Single-replica deployments are unchanged.
- **Off-machine backups.** Automatic backups can be copied to S3 (append-only) and/or by email, and the backup store itself can live in S3. **Admin -> Backups** now truly sets the schedule and retention for every account; before, it only changed the administrator's own.
- **Switching attachment storage** between local disk and S3 now copies existing attachments across automatically.
- **Admin -> Users** shows how much backup and attachment storage each user takes.
